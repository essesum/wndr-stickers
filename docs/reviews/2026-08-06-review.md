- **Авторство в callback'ах.** `_produce(requester=query.from_user)` — квоты и авторство пишутся на человека, а не на бота. Комментарий в коде объясняет почему.

## 1. 🔴 Критично — fallback-цепочка провайдеров мертва

### Суть

`.env`:
```
HTTPS_PROXY=http://127.0.0.1:10811
```

`deploy/wndr-stickers.sb`:
```lisp
(deny network-outbound (remote tcp "localhost:10811"))
```

`skill/wndr_stickers/src/imagegen.py:423`:
```python
proxy = settings.https_proxy or None
```
раздаётся в `generate_openrouter`, `generate_openai`, `generate_gemini`.
`generate_codex` proxy **не получает** — ходит напрямую. Поэтому бот и работает.

### Доказательство

Под боевым профилем `deploy/wndr-stickers.sb`:

```
xray-balancer слушает:          127.0.0.1:10811 (LISTEN, PID 72145)
connect 127.0.0.1:10811 без sb: OK
connect 127.0.0.1:10811 под sb: BLOCKED — PermissionError [Errno 1]
connect localhost:10811 под sb: BLOCKED — PermissionError [Errno 1]
httpx через proxy под sb:       FAIL — ConnectError [Errno 1] Operation not permitted
```

То есть `openrouter_gpt`, `openai` и `gemini` под LaunchAgent недостижимы **всегда**, а не иногда.

### Нужен ли proxy вообще — нет

Прямая доступность под тем же sandbox-профилем:

```
telegram    HTTP 302
openrouter  HTTP 200
gemini      HTTP 403
openai      HTTP 401
```

403 у Gemini — это не гео-блок. Тело ответа:
```json
{"error":{"code":403,
  "message":"Method doesn't allow unregistered callers (callers without
             established identity). Please use API Key or other form of
             API consumer identity to call this API.",
  "status":"PERMISSION_DENIED"}}
```
Это «нет ключа в запросе» на неаутентифицированный `GET /v1beta/models`. Гео-блок Google отдаёт другое сообщение (`User location is not supported for the API use`). 401 у OpenAI — то же самое.

### Репо само это предписывает

`.env.example`:
```
# ---- Сеть ----
# Пусто по умолчанию: runtime sandbox блокирует loopback/shared local services.
# Если нужен внешний HTTPS proxy, укажи не-localhost URL явно.
HTTPS_PROXY=
```
Живой `.env` нарушает собственный документированный контракт репозитория.
Похоже, паттерн VPN-маршрутизации скопирован из остальных ботов (см. `project_vpn_failover`), где нет Seatbelt-профиля с deny на 10811.

### Чем это плохо на практике

Цепочка `codex,openrouter_gpt,gemini` выглядит как отказоустойчивая, но отказоустойчивости нет. Протухнет `codex login` или кончится подписка ChatGPT — бот не переключится, а встанет целиком: `generate()` пройдёт все три ветки и бросит `ImageGenerationError("ни один провайдер не отдал картинку")`.

### Отдельно: preflight даёт ложную зелёную

`scripts/preflight.py` печатает
```
✓ цепочка: codex -> openrouter_gpt -> gemini
```
проверяя только наличие ключей и бинаря `codex` в PATH. Достижимость провайдера **из-под sandbox** не проверяется. Именно этот чек и должен был поймать проблему.

### Статус

**Решение Кати 2026-08-06: оставить как есть.** Риск принят осознанно: Codex по подписке — основной путь, он работает. Ни `.env`, ни `.sb` не изменены.

## 3. 🟡 Мелочь и латентное

### 3.1. `PACK_CAPACITY` — мёртвая настройка

```
config.py:52    pack_capacity: int = 120
config.py:106   "pack_capacity",          # только в валидаторе _blank_means_zero
```
Больше нигде. Задокументирована в `.env.example`, лежит в `.env`, не читается никогда. Переполнение ловится по строке ошибки Telegram (`is_pack_full`), а не по этому числу. Либо использовать, либо убрать — сейчас она вводит в заблуждение.

### 3.2. `INSERT OR REPLACE` + выключенные foreign keys

`db.py:229` — `INSERT OR REPLACE INTO stickers`, при `UNIQUE(slug, version)`.
`PRAGMA foreign_keys` не включается **нигде** (проверено grep'ом по всему репо; в SQLite он по умолчанию OFF).

Семантика `INSERT OR REPLACE`: при конфликте старая строка **удаляется**, новая получает новый rowid. Последствия, если это случится:

- `community_vectors.sticker_id` (PK, `REFERENCES stickers(id) ON DELETE CASCADE`) — каскад **не сработает**, останется висячая строка;
- `community_actions.sticker_id` — то же, история осиротеет;
- если у старой строки было `in_pack=1`, новая получит дефолт `0` при физически живом стикере в Telegram-паке.

Сейчас недостижимо: `naming.reserve` занимает `slug-vN.webp` через `touch(exist_ok=False)`, поэтому пара (slug, version) не повторяется. Но **защита держится на файловой системе, а не на схеме БД**. Достаточно почистить `stickers_dir` руками при живой БД — и коллизия станет достижимой.

Дёшево закрывается: `PRAGMA foreign_keys=ON` в `init_db` + `INSERT` вместо `INSERT OR REPLACE` (пусть падает громко).
